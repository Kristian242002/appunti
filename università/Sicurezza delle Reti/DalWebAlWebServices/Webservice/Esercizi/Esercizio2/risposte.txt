È un'opportunità, non un problema. Il client e il server comunicano esclusivamente tramite un formato testuale standard (richiesta HTTP con parametri nell'URL, risposta in JSON), completamente indipendente dal linguaggio di programmazione usato per implementarli. Client e server non hanno bisogno di "capirsi" a livello di codice — devono solo rispettare lo stesso contratto (stessa struttura di URL, stesso formato di risposta). Questo permette di scegliere il linguaggio più adatto per ciascun componente (es. C per il server per efficienza, Java per il client per portabilità) senza vincoli di compatibilità, dimostrando uno dei vantaggi chiave delle architetture SOA/webservice.
